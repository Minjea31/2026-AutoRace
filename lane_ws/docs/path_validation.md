# 반사광 필터·Center Path·GUI 개선 검증

이 문서는 다차로 확장 **직전 버전**의 검증 기록이다. 이후 변경과 빨강/파랑/초록 시각화 결과는 [최신 다차로 검증](multilane_validation.md)을 참고한다.

2026-11-02, 로컬 `lane_ws` 브랜치. 변경은 `lane_ws/` 내부이며 push/merge, 실차 제어 토픽·메시지·다른 워크스페이스 변경은 없다. 좌우 경계 색은 사용자 최종 요청에 따라 **동일한 청록색**이다.

## 구현

- HSV/HLS 기본 색상 임계값은 그대로 두고 BEV에서 연결 요소, 띠 폭, 곡선에 수직인 두께와 변동, 양쪽 경계 밝기 대비, 세로 지지율·내부 끊김, 곡률·잔차를 검증한다. 픽셀 행마다 대비로 잘라내는 방식은 실제 Bag의 흐릿한 테이프까지 끊어서 제외했다. 최종 구현은 후보 전체의 대비 중앙값을 쓴다.
- 상·중·하 histogram과 이전 경계에서 이동 검색창을 시작해 중심점을 수집하고 기존 RANSAC/지그재그 피팅을 재사용한다. 후보 수와 탈락 수를 GUI에 표시한다. 탈락 수는 중복 검색 시도도 포함하므로 물체 수가 아니다.
- 경계 쌍은 예상 폭·세로 폭 변화·후보 점수·이전 Center Path를 함께 평가한다. `/current_lane=false`는 좌측 경계, true는 우측 경계 우선이며 초기 동률 해소에도 쓴다. 이미 잡은 차로를 Bool 변경만으로 건너뛰지 않는다. A/B 선택은 별도 입력과 기존 상태 기계를 유지한다.
- Center Path는 좌우 경계의 중간 2차 곡선이다. 단일 차선은 기대 폭의 절반으로 추정한다. 폭 학습 범위도 설정 폭 주변으로 제한하여 잘못된 검출로 폭이 계속 누적 변화하지 않게 했다.
- 갑작스러운 후보 전환은 연속 확인하고, 이후 경로 전체를 신뢰도 기반 평활·변화율 제한한다. 경계 연계는 목표 행부터 가까운 구간에서 검사하여 관측되지 않은 먼 구간 외삽이 정상 곡선을 거부하지 않게 했다. 오랫동안 관측하지 않은 경계는 만료한다.
- Lookahead Target은 Center Path의 목표 행에 놓인다. 기존 조향식·조향 변화율·속도 상한을 재사용한다. 소실 경로는 `lost_hold` 동안만 신뢰도·속도를 줄이며 유지하고 이후 없애고 정지한다.
- GUI: 동일 청록색 좌우 경계 / 초록 Center / 빨강 Target / 자홍 차량 중심·오차 / 회색 소실 예측. 목표점이 화면 밖이면 가짜로 가장자리에 옮기지 않고 방향 화살표를 표시한다. Binary는 전·후·나란히 비교를 선택한다. 전은 색상+ROI, 후는 구조적으로 유효한 후보의 지지 픽셀이다.
- ROI와 BEV는 별도 편집 모드이며 ROI 네 변·모서리와 BEV 네 모서리를 드래그한다. 두 설정은 서로 바뀌지 않는다. 새 파라미터도 공통 schema를 통해 GUI, YAML, 노드의 atomic 적용에 연결된다. 영상 합성과 QImage 변환은 worker에서 처리하고 QWidget 렌더링은 Qt 스레드에서 한다.

## 재현 근거

전후 소스와 실행 파일은 작업 시작 시 로컬 `artifacts/path_upgrade/`에 보관했다. `before_source/`는 원본, `baseline_source/`는 동작을 바꾸지 않고 CSV 계측만 추가한 이전 버전이며 `before_benchmark`가 그 실행 파일이다. 이전 버전에는 명시적인 전체 Center Path가 없었으므로 그 프레임에서 선택한 경계와 반 차로 폭으로 **암묵적 경로**를 계측하고 실제 기존 target/steering은 그대로 기록했다. 색상·ROI·BEV·차로 폭·기존 제어 설정은 전후 동일하다. 신규 필터/추적 설정은 현재 기본값을 사용한다.

원본 Bag: `/mnt/Ubuntu_Data/autorace_bags/lane_20261012_125620`, `/camera/color/image_raw` RGB8 640×480, 3,311프레임, 162.583초. 다른 SSD에서 읽기 전용으로 처리했다. `/current_lane`, `/yolo/LR_sign` 기록은 없다. 전체 전후 CSV·구간별 요약·그래프와 13개 프레임 시각화는 `artifacts/path_upgrade/`에 있다. `artifacts/COLCON_IGNORE`로 보관 소스가 colcon 패키지 탐색에 들어가지 않게 했다.

## 결과 해석과 남은 한계

경로 변화량 감소는 정확도를 뜻하지 않는다. 원본 Bag에는 정답 경계·주행 경로 라벨과 카메라 보정값이 없고, 차선에 거의 수평으로 접근하거나 트랙 밖 가구를 보는 구간도 있다. x(y) 단일값 2차 곡선으로 나타낼 수 없는 급격한 U자/수평 차선은 여전히 어려우며, 짧은 지지 구간은 의도적으로 거부한다. 초기 기본 BEV가 실제 카메라의 바닥 투영과 다르면 폭 검증·단일 차선 경로·m 단위 오차도 부정확하다.

실제 밝은 반사 띠가 테이프와 비슷한 폭·형태·대비를 가지면 후보로 남을 수 있다. 시간 평활은 잘못 선택한 경로도 부드럽게 만들 수 있다. 검출 수가 줄거나 정지 수가 늘어난 결과를 모두 오검출 개선이라고 해석하지 않는다. 이 보고서의 검출/정지 수와 구간별 성능 저하를 함께 확인해야 한다.

실제 다차선 구간 평가는 흰 외곽선·노란 중앙선이 동시에 보이는 구간까지이며, 정답이 있는 독립 다차로 선택은 합성 Bag으로 확인했다. 실제 A/B·지그재그 미션 성공, 실차 폐루프 주행, 모니터 compositor의 화면 부드러움은 이번 검증 범위에 포함되지 않는다.

## 전체 실제 Bag 전후 비교

같은 Bag을 순차 처리하고 역방향 seek 재현성도 검사했다. Release/OpenCV 내부 스레드 1, 디스크 캐시를 비우지 않은 실행이다. 처리량은 시각화 JPEG 저장까지 포함한 wall time, 프레임 평균/p95는 읽기+디코딩+CV이며 디스플레이 FPS와 다르다.

| 항목 | 이전 | 개선 |
| --- | ---: | ---: |
| 전체 오프라인 처리량 | 202.14 FPS | 67.30 FPS |
| 읽기+CV 평균 | 4.91 ms | 14.78 ms |
| 읽기+CV p95 | 6.52 ms | 20.81 ms |
| 양쪽 검출 | 549 | 86 |
| 단일 경계 검출 | 2,233 | 2,117 |
| 경계 미검출 | 529 | 1,108 |
| 계산 속도 0 | 339 | 696 |

추가 후보 검색·구조 검증으로 CV 비용이 약 3배가 됐지만 이 실행의 p95는 기록 카메라 평균 주기 약 49ms 이내였다. 기존의 잘못된 경계 쌍도 폭 검증에서 탈락하므로 양쪽 검출 수가 크게 줄었다. 동시에 실제 급곡선/짧게 보이는 정상 경계를 놓치는 문제가 남아 있으며 검출·정지 수만으로 어느 쪽의 영향인지 분리할 수 없다. 현장 보정/정답 라벨 없이 전체 검출 정확도가 좋아졌다고 주장하지 않는다.

### 구간별 연속성

Target Δ p95는 **양 버전에서 모두 경계를 실제 검출한 같은 연속 프레임 쌍**의 목표 x 변화량이다. 개선판의 소실 예측 프레임만 넣어서 수치를 낮추지 않았다. steering Δ는 해당 구간 전체 연속 프레임을 사용한다. 1초 이상 시간 점프는 제외한다. 단위는 px/frame, rad/frame이며 주행 정확도나 도로 좌표의 곡률 오차가 아니다.

| 구간(0-based frame) | 관측 프레임 전→후 | 정지 전→후 | Target Δ p95 전→후(px) | steering Δ p95 전→후(rad) |
| --- | ---: | ---: | ---: | ---: |
| 전체 0–3310 | 2782→2203 | 339→696 | 35.48→8.20 | 0.04797→0.01756 |
| 직선 0–349 | 350→347 | 0→0 | 1.52→1.80 | 0.00331→0.00155 |
| 급곡선 450–599 | 88→71 | 46→57 | 15.95→4.72 | 0.03847→0.00725 |
| 단일 경계 1600–1799 | 195→165 | 0→23 | 72.36→3.55 | 0.04282→0.00061 |
| 강한 반사 2050–2299 | 247→139 | 8→43 | 69.83→8.49 | 0.04815→0.01543 |
| 여러 경계 2950–3099 | 106→81 | 33→59 | 13.95→7.39 | 0.06244→0.02080 |

직선의 Target Δ p95는 1.52→1.80px로 소폭 증가했다. 다른 구간의 변화량은 줄었지만 지연·보수적 거부의 영향도 있으며, 급곡선 관측과 정지 수는 이전보다 나빠졌다. 구간명은 샘플 영상을 보고 붙인 설명이지 정답 라벨이 아니다.

### GUI 처리와 렌더링

Qt offscreen, 실제 Bag 15초 실행에서 이전/현재 앱을 차례로 실행했다. 자동화는 이전 프레임·중간 seek·일시정지 튜닝·드래그·2× 재개를 수행한다. 새 GUI는 BEV 드래그와 추가 필터 변경을 더 수행하므로 평균 FPS는 고정 1× 재생 시험이 아니다. 아래 실행에는 PNG 저장을 넣지 않았다.

| 항목 | 이전 GUI | 최종 GUI |
| --- | ---: | ---: |
| 표시 프레임 | 413 | 422 |
| 평균 표시 FPS | 28.46 | 27.94 |
| 결과 준비→렌더 평균 | 8.07ms | 7.89ms |
| Qt timer 최대 간격 | 19.63ms | 19.62ms |

추가 CV 계산과 Binary 비교 영상이 들어가도 렌더링 지연은 비슷했다. 실제 모니터 출력 시험은 아니므로 화면 끊김이 모든 환경에서 해결됐다고 단정하지 않는다. 별도 실행으로 저장한 [GUI 화면](../artifacts/path_upgrade/gui.png)은 ROI/BEV 손잡이·Binary 전후 비교·Center Path·오차/신뢰도 표시를 보여준다. 스크린샷 시점에는 목표점이 화면 밖이어서 방향 화살표가 표시된다.

최종 실시간 실행은 raw 159회 송신/126회 수신/127회 처리/127회 표시, JPEG 148회 송신/142회 수신/143회 처리/141회 표시였다. 표시 FPS는 각각 24.09/28.87이며 준비→렌더 평균 7.67/8.12ms, timer 최대 18.87/18.89ms였다. 파라미터 변경에 의한 동일 프레임 재계산으로 처리 수가 수신보다 많을 수 있다. 예전 raw 측정보다 이번 수신률이 높았으나 DDS/시스템 전송 변동이 있으므로 이번 CV 수정의 효과로 해석하지 않는다.

최종 코어·GUI·설정과 이전 실행 파일의 SHA-256 근거는 `artifacts/path_upgrade/manifest.json`에 기록했다. 결과 파일은 Git 제외 대상이며 다른 PC에서는 [README 재현 명령](../README.md#검증과-재현)으로 다시 생성한다.
