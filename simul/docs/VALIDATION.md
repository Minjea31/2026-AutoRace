사용자가 실행 중인 GUI 시뮬레이터의 **도메인 42**에도 별도 구독자를 연결했다. 카메라 JPEG·raw RGB·Depth·두 CameraInfo·라이다·IMU·odom을 반복 수신하고 센서 stamp가 진행하는 것을 확인했다. raw RGB는 640×480 `rgb8`, Depth는 640×400 `16UC1`, 라이다는 245샘플이었다. 이 확인에서는 GUI 시뮬레이터에 제어·리셋·일시정지 명령을 보내지 않았다. [실행 중 센서 수신 결과](ros-live-check.json)

동시에 base 터미널의 도메인 0에는 `/cmd_vel` 발행자만 있고 센서 토픽이 없음을 확인했다. 실제 원인은 시뮬레이터와 ROS CLI 터미널의 도메인 불일치였다. 이를 맞추기 위해 Conda가 필요 없는 `simul/ros2.sh`를 추가하고, 시뮬레이터와 CLI가 같은 `ros_env.sh`를 사용하도록 했다. 도메인은 시작 로그와 화면에도 표시한다. 이후 기본 터미널의 도메인 0이 그대로 유지되는 재발을 확인하여, 현재는 기본값 0을 시뮬레이터용 42로 맞춘다. 0이 아닌 사용자 지정 도메인은 유지하고, 의도적인 도메인 0은 AUTORACE_SIM_DOMAIN_ID=0으로 선택한다. 기존 CLI 데몬의 발견 결과가 실제 DDS와 다른 현상도 확인하여 ros2.sh의 토픽 조회는 직접 DDS를 사용한다.

`ROS_DOMAIN_ID=144 ROS_LOCALHOST_ONLY=1 python simul/tools/check_ros_topics.py --cli-command`로 실제 `simul/ros2.sh topic pub -r 20` 명령을 사용하는 별도 오프스크린 검증도 수행했다. [CLI 주행·센서 검증 결과](ros-cli-check.json)

후속 요청에 따라 `ros_env.sh`의 `ROS_LOCALHOST_ONLY`를 `1`로 고정했다. 부모 셸에 `0`을 지정하고 `ros_env.sh`와 Conda용 `env.sh`를 각각 읽어 두 경우 모두 `1`이 되는지 확인했다. 이 조건에서 별도 도메인 144의 CLI 주행·전체 센서·TF·watchdog·일시정지·리셋 검사도 다시 통과했다.

기존 GUI도 같은 `--mission track --view overview` 옵션으로 재시작했다. 시작 로그에서 `ROS_DOMAIN_ID=42`, `ROS_LOCALHOST_ONLY=1`을 확인하고, 로컬 구독자로 위 8종 센서를 반복 수신하여 갱신된 [실행 중 센서 수신 결과](ros-live-check.json)에 기록했다. `simul/ros2.sh topic list -t`에서도 카메라·라이다·IMU·odom·TF 토픽을 확인했다.

## 검증 범위

그래픽 검증은 EGL/Mesa 소프트웨어 렌더러를 사용했다. `colcon list` 패키지 인식, `colcon build`, 설치된 `ros2 launch --show-args`도 통과했다. 최신 검증은 사용자가 생성한 실제 Conda `autorace-simul` 환경에서 `run.sh`, 22개 자동 검사, 연속 렌더링, 별도 DDS 도메인 143의 ROS 송수신으로 수행했다. 환경 패키지를 추가 설치하거나 변경하지 않았다. 실제 LIMO 하드웨어와 실제 카메라 K/D·외부 보정은 검사에 포함되지 않는다.

선택 `parking_adapter`는 변환 계산만 단위 검사했다. 현재 검사 호스트에는 `ackermann_msgs`가 설치되어 있지 않아 해당 타입을 통한 실제 DDS 연결은 아직 검증하지 않았다. 기본 `/cmd_vel` ROS 인터페이스는 위 통합 검사에 포함된다.
