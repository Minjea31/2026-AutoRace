# 저장 중앙 경로 추종

추종 가능한 새 중앙 경로는 해당 스캔 시각의 `odom <- base_link` TF로
변환해 메모리에 저장한다. 이후 저장 경로를 기본 추종 대상으로 유지한다.
최신 `base_link <- odom` TF로 저장 경로를 변환하고, 이미 지나간 구간을
제외해 기존 제어기로 추종한다.
경로 점의 순서는 유지하며 거리순으로 다시 정렬하지 않는다.

- 저장 경로 주행 속도 상한: `control_memory_speed` (기본 0.15 m/s)
- 마지막 점 도착 허용 거리: `control_memory_goal_tolerance` (기본 0.08 m)
- 스캔 수신·측정 시각 허용 지연: `control_timeout` (기본 0.50 s)
- 저장 경로용 TF 허용 지연: `control_memory_tf_timeout` (기본 0.20 s)
- 저장 경로에서 허용하는 거리: `control_max_path_distance` (기본 0.50 m)

새 경로가 짧거나 같은 끝점까지만 보이면 저장 경로를 변경하지 않는다.
새 경로가 기존 끝점 0.10 m 이내를 지나고 방향 차이가 90도 이내이며,
그 너머로 경로를 따라 0.05 m 넘게 이어질 때만 꼬리 구간을 추가한다.
기존 경로의 앞 구간을 새 관측으로 덮어쓰지 않는다. 끝점의 차량까지 직선거리는
비교에 사용하지 않아, 커브를 돌아 차량 가까이 오는 연장도 허용한다.
끝점에 도착한 뒤 같은 경로가 다시 보여도 주행을 재개하지 않으며,
연결 가능한 연장 구간이 관측되면 다시 추종할 수 있다.

마지막 점에 도착하거나 지나가면 `memory_goal_reached`로 정지한다.
관측된 적 없는 구간으로 외삽하지 않는다. 스캔 수신·측정 시각 시간 초과는
정지하되 저장 경로를 보존한다(`paused_scan_timeout`). 최신 스캔과 TF가 복구되면
현재 위치에서 남은 경로의 추종 가능성을 검사해 재개한다. 시간 초과 중에는
저장 경로로도 주행하지 않는다. 시각 역행·잘못된 스탬프·스캔 TF 오류·미션 종료는 기억을 지우며,
저장 경로 주행 중 TF가 없거나 오래됐으면 정지한다. 새 경로가 비었거나
생성된 새 경로가 추종 불가능해도 저장 경로를 별도로 검사해 유효하면 추종한다.
추종 불가능한 새 경로로 저장 경로를 갱신하지 않는다. 저장 경로도 사용할 수
없으면 정지하며, 정지 사유에는 `memory_path_no_usable_forward_segment`처럼
저장 경로의 실패 원인을 표시한다.

로그의 `memory` 항목과 `Memory Path Feedback` 제어 상태로 동작을 확인할 수 있다.
`Path update` 줄은 새 경로의 갱신 결과를 별도로 표시한다. 끝점 도달이나
추종 실패로 `memory` 상태가 바뀌어도 갱신을 거부한 이유를 확인할 수 있다.
새 경로가 없거나 추종 불가능해 갱신하지 않으면 `not_attempted: ...`로 표시한다.
`stored`는 최초 저장, `extended`는 연장, `kept_shorter_path` 또는
`kept_no_aligned_extension`은 기존 경로 유지, `following`은 유효한 새 경로 없이 추종 중이다.
RViz의 기존 중앙 경로 MarkerArray에는 남은 저장 경로가 주황색으로 표시된다.
이는 경로 검출 소실에 대한 보완이며 별도 장애물 충돌 검사를 추가하지는 않는다.
프로세스 재시작 후에는 저장 경로가 없다.
