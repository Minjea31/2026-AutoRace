# 저장 중앙 경로 추종

추종 가능한 새 중앙 경로는 해당 스캔 시각의 `odom <- base_link` TF로
변환해 메모리에 저장한다. 이후 저장 경로를 기본 추종 대상으로 유지한다.
최신 `base_link <- odom` TF로 저장 경로를 변환하고, 이미 지나간 구간을
제외해 기존 제어기로 추종한다.
경로 점의 순서는 유지하며 거리순으로 다시 정렬하지 않는다.

새 경로 생성에서 법선 교점·최근접 투영은 좌우 경계가 각각 3점 이상일 때만
사용한다. 한쪽이 3점 이상이고 반대쪽이 0~2점이면 유효한 학습 폭으로
한쪽 경계 기반 경로를 추정한다. 반대쪽에 남은 최대 2점은 모두 추정 경계와
폭의 25% 이내로 일치해야 한다. 양쪽이 모두 2점 이하이면 새 경로를 만들지
않고 저장 경로를 검사하며, 저장 경로도 사용할 수 없으면 정지한다.

마지막 신뢰 가능한 학습 폭은 시간에 따른 만료 없이 유지한다.
새 폭 측정이 불안정하면 그 측정만 버리고 이전 폭과 측정 시각을 유지한다.
한쪽 경계로 추정한 폭은 재학습에 사용하지 않는다. 미션 종료 시에는 초기화한다.

- 저장 경로 주행 속도 상한: `control_memory_speed` (기본 0.15 m/s)
- 마지막 점 도착 허용 거리: `control_memory_goal_tolerance` (기본 0.08 m)
- 저장 경로 복구 시 새 경로까지 최대 거리: `control_memory_recovery_distance` (기본 0.15 m)
- 스캔 수신·측정 시각 허용 지연: `control_timeout` (기본 0.50 s)
- 저장 경로용 TF 허용 지연: `control_memory_tf_timeout` (기본 0.20 s)
- 저장 경로에서 허용하는 거리: `control_max_path_distance` (기본 0.50 m)

새 경로가 짧거나 같은 끝점까지만 보이면 저장 경로를 변경하지 않는다.
새 경로가 기존 끝점 0.10 m 이내를 지나고 방향 차이가 90도 이내이며,
그 너머로 경로가 조금이라도 이어지면 꼬리 구간을 추가한다.
같은 끝점의 수치 오차를 제외하기 위한 허용 오차는 1e-8 m이다.
기존 경로의 앞 구간을 새 관측으로 덮어쓰지 않는다. 끝점의 차량까지 직선거리는
비교에 사용하지 않아, 커브를 돌아 차량 가까이 오는 연장도 허용한다.
저장 경로가 유효하면 위 연장 조건만 사용한다. 저장 경로가 추종 불가능하거나
끝점에 도달하면, 현재 위치에서 0.15 m 이내로 연결되고 전방 45도 이내 방향인
유효한 새 경로로 교체할 수 있다. 최소 남은 길이 제한은 없다. 이때는 기존 끝점과
연결될 필요가 없다. 교체 검사는 스캔 시각의 저장용 TF와 최신 현재 위치 TF를
모두 요구한다. 실제로 남은 구간이 없거나 멀거나 방향이 맞지 않으면 기존 경로를 지우지 않고
정지한다. TF 실패는 경로 교체로 우회하지 않는다.

마지막 점에 도착하거나 지나가면 `memory_goal_reached`로 정지한다.
관측된 적 없는 구간으로 외삽하지 않는다. 스캔 수신·측정 시각 시간 초과는
정지하되 저장 경로를 보존한다(`paused_scan_timeout`). 최신 스캔과 TF가 복구되면
현재 위치에서 남은 경로의 추종 가능성을 검사해 재개한다. 시간 초과 중에는
저장 경로로도 주행하지 않는다. 시각 역행·잘못된 스탬프·스캔 TF 오류·미션 종료는 기억을 지우며,
저장 경로 주행 중 TF가 없거나 오래됐으면 정지한다. 새 경로가 비었거나
생성된 새 경로가 추종 불가능해도 저장 경로를 별도로 검사해 유효하면 추종한다.
추종 불가능한 새 경로로 저장 경로를 갱신하지 않는다. 저장 경로도 사용할 수
없으면 정지하며, 정지 사유에는 `memory_path_no_usable_forward_segment`처럼
저장 경로의 실패 원인을 표시한다.

로그의 `memory` 항목과 `Memory Path Feedback` 제어 상태로 동작을 확인할 수 있다.
`Path update` 줄은 새 경로의 갱신 결과를 별도로 표시한다. 끝점 도달이나
추종 실패로 `memory` 상태가 바뀌어도 갱신을 거부한 이유를 확인할 수 있다.
새 경로가 없거나 추종 불가능해 갱신하지 않으면 `not_attempted: ...`로 표시한다.
`stored`는 최초 저장, `extended`는 연장, `kept_shorter_path` 또는
`kept_no_aligned_extension`은 기존 경로 유지, `following`은 유효한 새 경로 없이 추종 중이다.
`replaced_unusable_memory`는 추종 불가능한 저장 경로를 현재 위치에 연결되는
새 경로로 교체했음을 뜻한다. 복구 실패는 `recovery_too_far_from_vehicle`,
`recovery_direction_mismatch`, `recovery_insufficient_forward_path`로 구분한다.
RViz의 기존 중앙 경로 MarkerArray에는 남은 저장 경로가 주황색으로 표시된다.
이는 경로 검출 소실에 대한 보완이며 별도 장애물 충돌 검사를 추가하지는 않는다.
프로세스 재시작 후에는 저장 경로가 없다.

## 단일 경계 코너 처리

통합 경로의 법선 오프셋은 각 관측 경계 선분의 평행 이동과 인접 직선 교점으로
생성한다. 오프셋의 자기 교차 루프를 제거한 뒤 코너 주변을 5차 곡선으로
연결한다. 경계의 거의 반대 방향 연결은 콘 연관 오류 후보로 거부한다.
실제 경계의 안쪽, 경계 교차, 점 간격, 꺾임, 자기 교차와 경계상의 진행 순서를
검사한다. 차선 반대쪽이 관측되지 않은 구간에서는 보이지 않는 경계까지의
차량 여유 공간을 보장하지는 않는다.

`center_min_turn_radius` 기본값은 0.2630871384 m로, 차량 mux 설정의
휠베이스 0.20 m / tan(조향 한계 0.65 rad)에서 계산했다. 실제 차량 설정이
변경되면 함께 조정한다. 샘플 경로의 세 점 외접원 곡률로 최소 회전반경을
검사한다. 통과하지 못하면 단일 경계 경로는 사용하지 않고, 연장부에서는
정상 단면 구간을 유지한다. 기존 조향 감속에 곡률 기반 감속을 추가하되
백업 속도 상한과 조향 변화율 제한은 유지한다.

진단에는 corners, trimmed_loops, max_curvature_per_m, min_radius_m,
corner_smoothing 또는 corner_failure가 출력된다. 이는 궤적 기하 검사이며
차량 동역학이나 전체 차체 충돌 검증을 대체하지 않는다.

## 독립 경계 재탐색
직전 스캔의 odom 좌표와 현재 콘을 0.12m 이내 일대일 대응해 소속을 유지한다.
미검출 점을 보관하지 않는다. 끊긴 쪽 첫 점은 유지된 쪽의 대응 선분과 학습 차폭 ±25%로 검증한다.
유효 선분 또는 학습 차폭이 없으면 이미 대응된 반대쪽 콘을 제외한 y 부호 초기화를 사용한다.

## 中央 경로 실패 시 오프셋 재시도
대응 단면이 있어도 measured 중앙 경로가 2점 미만이거나 기하 검증에 실패하면 기존 한쪽 경계 오프셋 생성을 시도한다. 학습 차폭과 경계 3점 이상 조건, 반대편 점 차폭 검사, 교차와 곡률 검증은 유지한다. offset_fallback 진단으로 전환 원인을 표시한다.
