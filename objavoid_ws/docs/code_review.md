# 현재 제어 구성

제어는 단일 objavoid_node의 node.py에 있다. 센서·군집 처리, 가까운 차체 패스 검사,
회피/정렬/차선 주행과 ROS 제어 입출력을 담당한다.
RViz 마커/Path 발행은 visualization.py로 분리했으며 노드는 여전히 하나다.

1. 직진 통로가 안전하면 직진한다. 회피 진입용 앞보기는 기본 1m다.
2. 정면 장애물을 우선 피하고, 그 뒤에 검출된 클러스터 중 가장 가까운 장애물의
   반대 방향을 회피 선호로 삼는다. 뒤 클러스터가 없거나 중앙이면 가까운 패스 여유로 정한다.
3. 실제 이동 패스는 최소 0.15m~최대 0.7m에서 긴 구간 우선으로 검사한다.
4. 장애물 옆 통과를 확인하면 방향 잠금을 해제하고 정렬 또는 새 회피를 시작한다.
5. 정렬 이후 최신 lane 중심을 따르며 lane 만료 시 odom을 보조로 쓴다.

정렬 후 2m 직진 출구 검사는 잘못 추가된 조건이어서 제거했다. 출구 연결 함수와
가중 평균 통로 점수 계산도 삭제했다. 정면 장애물 뒤 클러스터는 방향 선택에만 쓰고,
최종 이동 후보의 차체 충돌/도로 이탈 검사는 유지한다.

visual_road_distance는 RViz 참고선 표시 길이이며 제어 조건이 아니다.
NumPy 일괄 점 검사, 최신 스캔 1개 수신 및 계산 후 만료 검사는 유지한다.
같은 720점 재현의 방향/패스 계산은 약 1~2ms로 줄었다. 전체 환경의 주기 보장을 의미하지 않는다.

## 표시·미사용 데이터 정리

현재 켜져 있는 패스/장애물 박스/차선 참고선/도로 외곽/차선 번호는 유지했다.
숨겨져 있던 부채꼴·화살표·거리/상태 라벨·차체·군집 점/라벨은 제거했다.
시각화는 같은 토픽과 주기로 발행하며 별도 노드나 런치를 추가하지 않았다.

rays와 objects 목록은 소비하는 곳이 없어 제거했고, 미사용 turning 속성과
버려지는 헤딩 보정 반환값/계산도 정리했다. 제어 조건/충돌 함수 17개의 AST가
변경 전과 동일함을 확인했고 40개 스캔/군집 입력의 실제 제어 데이터도 비교했다.
path_rejections 로그용 재검사와 일부 반복 좌표 계산은 기능상 사용하므로 남겼다.
